# 04 · 数据接入指南

当前 OHLCV 已接入 AKShare，其余 `scripts/` 仍是 `NotImplementedError`。本篇既说明这条
已实现链路，也讲怎么继续填空。

当前行情主源是东财 `stock_zh_a_hist`；日线主源失败时可降级到腾讯
`stock_zh_a_hist_tx`。降级不是“偷偷换接口”：tool 会把它写进 provenance 和
quality flags。周线/月线没有该备用链，失败时会如实返回 missing/degraded。

## 零、先分清 Tool 与 Data

“数据每天变化”并不意味着数据本身是 Tool。更准确的分层是：

```text
Agent（决定何时取数）
  → Tool（稳定动作：fetch_market_data）
    → Script/Adapter（AKShare 字段校验与归一）
      → External Data（每次变化的上游响应）
        → Artifact（本次 run 冻结下来的 ohlcv.json）
```

Tool 是动词，Data 是这次调用的结果。只有把动态结果冻结进 workspace，并附带
`fetched_at`、请求参数、数据源与字段映射，同学才能复现和审计一次 agentic run。

## 一、动手之前：先做选型决策

数据源不是随便挑一个就行，它决定了整个系统的能力上限。至少要回答：

| 问题 | 为什么重要 |
|---|---|
| 免费还是付费？ | 免费源的财务数据经常缺字段、缺历史 |
| 有没有**披露日**字段？ | 没有就无法避免前视偏差，所有回测都会虚高 |
| 复权数据是源头给还是自己算？ | 自己算要拿复权因子，多一个出错点 |
| 限流多少？ | 决定能不能批量分析 |
| 停牌日怎么返回？ | 有的源跳过，有的源返回前值——后者会毒化所有指标 |

**决策做完，写进 `memory/decisions/`。** 半年后你会忘记为什么选了它。

## 二、实现顺序（不要跳）

```
1. fetch_ohlcv              ← 已用 AKShare 接通，先演示最小工具链
2. fetch_trading_calendar   ← 下一步；完整时间序列对齐依赖它
3. clean.align_to_calendar  ← 立刻验证 1+2 的配合
4. store.save/load_block    ← 打通落盘
5. store.build_dataset_json ← 打通到契约，此时可跑 validate_artifact
   ── 到这里技术面分析就能跑了 ──
6. fetch_statements + align_by_disclosure_date + unify_units
   ── 到这里基本面分析能跑了 ──
7. fetch_announcements / fetch_news / fetch_moneyflow
   ── 到这里情绪面能跑了 ──
```

**第 5 步是关键里程碑**：它是数据层与契约层第一次接通，
跑通 `python tools/validate_artifact.py --artifact dataset` 就说明骨架真的通了。

## 三、A 股特有的六个坑

| 坑 | 症状 | 处理 |
|---|---|---|
| 单位不统一 | 营收忽大忽小 10000 倍 | `unify_units`，并打 warning flag |
| 停牌补值 | 均线在停牌区间莫名平滑 | 按日历跳过，不补 |
| 复权口径混用 | 均线与历史价格对不上 | 一个 dataset 内只允许一种口径 |
| 报告期 vs 披露日 | 回测收益虚高 | 一律按披露日对齐 |
| 涨跌停截断 | 动量指标失真 | 记录 `limit_days`，在 caveats 里声明 |
| 追溯重述 | 历史财务数据变了 | 标 flag，记录取数时间 |

**每踩一个新坑，写进 `memory/knowledge/datasource-gotchas.md`。**

## 四、实现一个函数的完整流程

以 `fetch_ohlcv` 为例：

```python
def fetch_ohlcv(req, freq="daily", adjust="qfq") -> DataBlock:
    # 1. 调数据源
    raw = source_client.daily(codes=req.codes, start=req.start, end=req.end, adj=adjust)

    # 2. 立刻检查：拿到的是不是我以为的东西
    if raw.empty:
        return DataBlock(status="missing", provenance=..., rows=0)

    # 3. 字段改名，记录 mapping（可追溯的关键）
    prov = Provenance(
        source="EXAMPLE_SOURCE_A",
        fetched_at=now_iso(),
        field_mapping={"trade_date": "date", "vol": "volume"},
        unit="CNY_yuan",
        params={"freq": freq, "adjust": adjust},
    )

    # 4. 质量检查，只标记不修改
    flags = []
    if len(raw) < expected_bars:
        flags.append(QualityFlag("ohlcv", "warning", "样本不足，长周期指标不可信"))

    # 5. 落盘 + 返回
    path = save_block("ohlcv", req.codes[0], raw, base_dir)
    return DataBlock(status="ok", rows=len(raw), path=path, provenance=prov, flags=flags)
```

注意第 2 步和第 4 步：**响亮地失败、如实地标注**，
这两件事比取数本身更能决定系统的可靠性。

## 五、收尾

实现完一个函数后：

1. `tests/` 补测试，至少覆盖「源返回空」和「源返回缺列」
2. 把 `tools/` 里对应工具的 `stub()` 换成真实调用
3. 改 `tools/tool_manifest.yaml` 的 `status: stub` → `implemented`
4. 改 `tools/README.md` 的状态表
5. 如果踩了新坑 → 写进 `memory/knowledge/`

## 六、运行当前 AKShare 教学示例

先创建 run，再调用工具；这里显式使用 `adjust=none`，因为复权策略尚未由人确认：

```bash
python tools/init_run.py --targets 600552.SH 600667.SH 603290.SH 300598.SZ 301047.SZ \
  --as-of 2026-08-28 --slug akshare-demo

python tools/fetch_market_data.py --run-id 2026-08-28_akshare-demo \
  --params-file config/market_data.demo.json
```

动态结果写到 `workspace/runs/2026-08-28_akshare-demo/data/ohlcv.json`。新闻源在
`config/datasources.yaml` 中为 `NONE`，因此这条示例链路不会调用 `fetch_news`。
