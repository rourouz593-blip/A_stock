# 从持仓截图更新 positions.yaml

## 0. 立场：你负责看，代码负责验

看图是你的能力，但**你读出来的数字不可信到能直接用**。
成本价读错一位，章节⑦的单笔风险与 0.5% 判断就全错了，而且错得很隐蔽——
报告照样能生成，数字照样很专业，只是全是假的。

所以流程是：**你读 → 工具用恒等式验 → 验过了才落盘。**

```bash
# ① 预览（会做算术自检）
python tools/import_positions.py --json '{"positions":[...]}'
# ② 确认无误
python tools/import_positions.py --json '...' --apply
# ③ 跑复盘
python tools/astock.py review --mode positions
```

## 1. 要读哪些字段

| 字段 | 必需 | 券商 App 里的常见叫法 |
|---|---|---|
| `code` | ✅ | 证券代码 / 代码（六位数字，后缀由工具推断） |
| `name` | 建议 | 证券名称 / 名称 |
| `shares` | ✅ | **持仓数量 / 股份余额 / 证券数量** |
| `cost` | ✅ | 成本价 / 摊薄成本 / 持仓成本 / 参考成本 |
| `price` | ✅ | 现价 / 最新价 / 市价 |
| `market_value` | ✅ | 市值 / 参考市值 |
| `pnl` | ✅ | 浮动盈亏 / 盈亏 / 参考盈亏 |
| `account_equity` | 建议 | 总资产 / 资产总值（**不是**总市值） |

后四个看起来"多余"，其实是**校验用的**：券商已经替你算好了，
读出来的四个数互相能对上，才说明没读错。少读一个，自检就废了。

## 2. 七个陷阱

### ① 可用 ≠ 持仓
A 股 T+1，当日买入的股票"可用"是 0，但"持仓数量"是全部。
**一律取持仓数量**，取可用会让仓位算少。

### ② 摊薄成本 ≠ 持仓成本
- **摊薄成本**：把历史已实现盈亏摊进去，可能是负数
- **持仓成本 / 参考成本**：本次建仓的加权均价（含手续费）

本项目要的是**持仓成本**。两个都显示时取持仓成本；
只显示摊薄成本时照读，但要在回话里说明——因为它会让盈亏比例失真。

### ③ 千分位与单位
`1,200` 是 1200 股；`1.2万` 是 12000。
A 股 App 一般显示"股"不是"手"，但看到 `12手` 要换成 1200 股。

### ④ 金额被隐藏
很多 App 有"隐藏资产"开关，数字显示成 `****` 或 `***.**`。
**看到这种直接停下来**，请用户关掉隐藏再截一张，不要猜。

### ⑤ 截图不完整
持仓多于一屏时，用户可能只截了上半部分。
读完主动问一句"是不是全部持仓"——
漏一只票，章节⑦的总仓位和同题材集中度就都是错的。

### ⑥ 分红送转之后
除权后成本价会被券商自动调整，与用户记忆中的买入价不一致。
**以截图为准**，这是券商的口径，不要去"纠正"它。

### ⑦ 非 A 股标的
港股通、基金、可转债、逆回购可能混在同一个持仓列表里。
本系统只处理 A 股股票，**其余的跳过并告知用户**，不要硬塞进去。

## 3. 输出格式

```json
{
  "account_equity": 200000,
  "positions": [
    {"code": "600519", "name": "示例", "shares": 100, "cost": 12.80,
     "price": 14.62, "market_value": 1462, "pnl": 182}
  ]
}
```

代码写六位即可，后缀由工具按板块推断；
若旧的 `positions.yaml` 里已有该代码，**工具会沿用旧文件里的后缀**。

## 4. 工具会怎么验你

两条恒等式，任一条对不上就打回：

```
shares × price          ≈ market_value      （差 > 1% 就报错）
(price − cost) × shares ≈ pnl               （差 > 2% 就报错）
```

报错时它会告诉你**多半是哪个字段读错了**。回去重看那一个数，别整张重读。

## 5. 你不能做的三件事

1. **不要猜 `thesis`（买入逻辑）。** 截图里没有这个信息。
   新标的的 thesis 留空，然后**问用户**："这只当初为什么买？"
   这是章节④的第一个问题，编一个等于毁掉整份复盘的价值。
2. **不要猜 `stop_level`（失效位）。** 同上，问用户。
   失效位应当在买入时就定好，不是事后由 AI 推一个。
3. **不要用 `--allow-unverified` 绕过自检**，除非你确认这个 App 真的不显示市值与盈亏。
   绕过等于把"数字可能是错的"这件事藏起来。

## 6. 隐私

持仓截图含真实账户信息。
- 读完就好，**不要把截图复制进仓库**（`.gitignore` 已挡掉常见图片格式）
- 不要把账户总资产写进 `positions.yaml`，它属于 `.env`
- 回话里不必复述完整的资产数字

## 7. 完整对话示例

> 用户：（上传截图）帮我更新持仓然后跑复盘

1. 读图 → 得到四只票的七个字段
2. 发现其中一只是可转债 → 跳过并告知
3. `import_positions.py --json '...'` → 自检通过，预览显示 1 只新增、1 只加仓
4. 新增那只没有 thesis → **先问用户**："`XXX` 是新买的，当初的买入逻辑是什么？失效位定在哪？"
5. 用户回答后写进 yaml → `--apply`
6. 总资产有变化 → 提醒改 `.env`
7. `python tools/astock.py review --mode positions`
