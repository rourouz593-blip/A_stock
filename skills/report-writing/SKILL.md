# 报告写作规范

## 1. 九章结构（固定，不得增删主章节）

| # | 章节 | 来源 | 要点 |
|---|---|---|---|
| ① | 市场总览 | `market.json.overview` | 五项数据 + 大盘状态 + 情绪阶段 |
| ② | 指数复盘 | `market.json.index_review` | 四段拆解 + 归因 + 关键位 |
| ③ | 板块与题材 | `sectors.json` | 五类方向 + 梯队 + 验证条件 |
| ④ | 我的持仓计划 | `positions_review.json.cards` | 一票一卡 + 七条自检 |
| ⑤ | 明日预案 | **本 agent 生成** | 三情景 + 仓位上限 + 时间轴 |
| ⑥ | 新闻与公告 | `news.json` | 三分类 + 次日验证 |
| ⑦ | 风险与纪律 | `positions_review.json.risk` | 仓位 + 单笔风险 + 是否停手 |
| ⑧ | 最终执行面板 | **本 agent 生成** | 八项，一屏看完 |
| ⑨ | 运行说明 | `run_manifest.json` | 模式、日期、数据完整性 |

## 2. 语言规范

- **结论先行**：每节第一句就是这一节的判断。
- **标注来源**：每条判断后标 `[market]` `[sectors]` `[positions]` `[news]`。
- **数字带口径**：写"两市成交额 1.02 万亿，较昨日 −830 亿（−7.5%）"，
  不写"成交额有所萎缩"。
- **不确定就写不确定**：禁止用"大概率""明显""显然"掩盖证据不足。
- **禁止**：目标价、具体买点、仓位建议之外的操作指令、新标的推荐。

## 3. 数据缺口的声明位置

任何一路 `blocked` → **报告开头第一句**就声明，不许放到末尾小字。

```
【数据缺口】本次分时数据未取到，章节二的日内四段拆解缺失，
其余章节不受影响。
```

## 4. 章节五：预案要写成 if-then

| ❌ | ✅ |
|---|---|
| 视情况减仓 | 若 A 低开超 3% 且 10:00 前不回补，减半仓 |
| 关注主线延续性 | 若 XX 板块 10:00 前出现第二只涨停，视为延续，持有不动 |

预案的意义是**在没有情绪压力的时候把决定做完**。
写"视情况而定"就完全失去了意义。

## 5. 章节八：执行面板的极简纪律

只有八项，**多一个字都不要**。

三个关键观察信号必须**不多不少正好三个**——
两个不够覆盖，四个就记不住，第二天开盘根本用不上。

"明天唯一纪律"必须是一句话，且是**可执行的禁令或规则**，
不是"保持冷静"这类情绪劝告。

## 6. HTML 仪表盘

`report.html` 由 `tools/render_report.py` 从 `report.json` 渲染，**不是手写**。

想改样式 → 改渲染器。在 agent 里拼 HTML 字符串是禁止的：
那样每天的报告长得都不一样，也没法版本管理。

模板见 `templates/report_template.md`，免责声明见 `templates/disclaimer.md`（必须原样附上）。

## 7. 硬约束回顾

- 不引入四份产物之外的任何新信息、新数字、新观点
- 不为报告完整而抹平矛盾——矛盾要单独写出来
- 每份报告附免责声明
