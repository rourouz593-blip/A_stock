# 持仓复盘方法

## 0. 这个技能的立场

**复盘的目的不是让人感觉良好，是让人少犯同一个错第二次。**

绝大多数散户的亏损不来自选股能力，来自七种可预测的行为偏差。
系统性地每天检查一遍，比多研究十个指标有用得多。

## 1. 卡片字段口径

### 个股地位
对照 `sectors.json` 的梯队判定，不要凭印象：龙头 / 中军 / 核心弹性 / 前排 / 后排 / 杂毛。
**"杂毛"要敢写。** 手里拿着后排票却以为自己在做龙头，是最危险的错觉。

### 三个相对强弱
| 基准 | 算法 | 说明什么 |
|---|---|---|
| 相对大盘 | 个股涨跌幅 − 上证涨跌幅 | 有没有跑赢市场 |
| 相对板块 | 个股涨跌幅 − 所属板块涨跌幅 | 在这个方向里是强是弱 |
| 相对核心 | 个股涨跌幅 − 板块龙头涨跌幅 | 离核心有多远 |

**三个都为负 = 这只票在最弱的位置**，无论账面是盈是亏。

### 买入逻辑是否仍成立
把 `positions.yaml` 里写的 `thesis` 拿出来逐字对照今天的盘面：

- 逻辑写"打板做龙头" → 它今天还是龙头吗？断板了吗？
- 逻辑写"板块启动初期低吸" → 板块现在还在启动期吗？还是已经到高潮了？
- 逻辑写"业绩预增" → 预增兑现了吗？股价反应完了吗？

判定：成立 / 部分成立 / **已失效** / 无法判断。
**"已失效"要敢写。** 逻辑失效还拿着，就已经不是原来那笔交易了。

### 三个价位
- **压力位**：上方最近的套牢区或前高
- **支撑位**：下方最近的成交密集区或均线
- **失效位**：破了就承认判断错了 —— 这个位置在**买入时**就该定，不是套了以后往下挪

### 唯一动作
持有 / 减仓 / 退出 / 禁止加仓 / 确认后可加仓 —— **只能选一个**。

> 写"可以持有也可以减一半"等于没给建议。
> 第二天早上 9:30 的人没有时间做二选一。

## 2. 七条行为自检

无论触发与否，七条都必须给出结论与依据。

| # | 行为 | 判定方法 | 为什么危险 |
|---|---|---|---|
| 1 | **卖强留弱** | 对比卖出票与留下票的相对强弱 | 组合会越留越弱，最后全是"等解套"的票 |
| 2 | **缩量下跌当洗盘** | 看有没有跌破关键位、板块是否同步走弱 | 缩量下跌也可能是没人要了 |
| 3 | **亏损补仓** | 检查浮亏票近期有没有加仓记录 | 把小错变大错，且突破了单笔风险上限 |
| 4 | **卖飞后追回** | 检查同一代码近期的卖出/买入序列 | 追回价通常在情绪高点 |
| 5 | **同一题材重复持仓** | 按 `sector` 字段聚合权重 | 三只同题材 = 一个仓位的三倍风险 |
| 6 | **板块回流时替弱票找理由** | 板块整体回流时，最弱票的持有理由是否变成"补涨" | "补涨"是最常见的自我安慰 |
| 7 | **短线失败后改长线** | 对比 `thesis` 与当前的持有理由 | 交易模块被偷偷改变，风险敞口失控 |

### 写法要求
**触发就指名道姓。** "存在一定的卖强留弱倾向"是废话；
"卖出的 A 相对板块 +2.1%，留下的 B 相对板块 −3.4%，这是典型的卖强留弱"才是结论。

这一节的价值就在于说不爱听的话。说得客气等于没说。

## 3. 优先级

| 优先级 | 什么票 |
|---|---|
| 优先保留 | 逻辑成立 + 相对强度为正 + 在梯队前排 |
| 继续观察 | 逻辑部分成立，或强弱信号矛盾 |
| 优先处理 | 逻辑已失效，或三个相对强弱全为负，或接近失效位 |

## 4. 硬约束

- 持仓股行情缺失（停牌）→ 那张卡片标 `blocked`，不许拿昨日价格假装今日。
- 不给目标价、不给具体买点、不推荐新标的。
- 本系统输出的是**给自己定的规则**，不是投资建议。
