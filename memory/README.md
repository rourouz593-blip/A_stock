# memory/ — 记忆层

## 这一层是什么

Agent 的上下文窗口是**一次性**的：这次 run 结束，它就什么都不记得了。
记忆层就是把"值得跨 run 保留的东西"落到磁盘上。

> 教学要点：记忆不是"把聊天记录存下来"。
> 记忆的核心是**筛选**——什么值得记、记多久、下次谁会用到。
> 记太多等于没记（检索不到），记太少等于每次重头再来。

## 三类记忆，不要混在一起

| 目录 | 记什么 | 生命周期 | 谁写 | 谁读 |
|---|---|---|---|---|
| `knowledge/` | 沉淀下来的稳定知识：口径约定、数据源踩坑、行业常识 | 长期，人工维护 | 人 / agent 提议人确认 | 所有 agent |
| `decisions/` | 做过的决定与理由（ADR）：为什么选这个数据源、为什么用前复权 | 长期，只增不改 | 人 | 所有 agent |
| `runs/` | 每次运行的摘要：结论、动作、数据缺口 | 中期，可归档 | astock | news-analyst 做次日验证、orchestrator |
| `positions_history.jsonl` | **只增不改**的持仓流水：成本、数量、当时浮亏、买入逻辑、失效位 | 长期 | import_positions / compute_risk | position-advisor 的行为自检 |

`MEMORY.md` 是**索引**，不是内容。每条一行，指向具体文件。
agent 先读索引，再决定要不要展开读某个文件——这样上下文才不会被撑爆。

## 为什么持仓流水要"只增不改"

章节④的七条行为自检里，有三条本质上是"**和过去比**"：
亏损补仓、卖飞后追回、短线失败后改成长线。

而人恰恰会在这三件事上骗自己——改完 thesis 之后，昨天写的是什么就没人记得了。
所以 `positions_history.jsonl` 只追加、不修改、不删除：**改过的历史就不是历史了。**

## 写入时机

- `knowledge/` — 每次发现一个新的口径坑、数据源限制、判断陷阱
- `decisions/` — 每次做出一个不可逆或影响全局的技术选择
- `runs/` — 每次 run 结束，由 orchestrator 自动追加

## 记忆 vs 技能：怎么分？

- **技能（skills/）** = 通用方法论，"分析财报要看哪六个维度"
- **记忆（memory/）** = 本项目的具体经验，"某某数据源的财报单位是万元，取回来要乘 10000"

方法论进 skills，踩坑进 memory。
