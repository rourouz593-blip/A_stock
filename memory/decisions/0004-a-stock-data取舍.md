# ADR-0004：a-stock-data 取什么、不取什么

- 日期：2026-09-01
- 状态：已采纳
- 对象：`/Users/chandler/Code/a-stock-data`（本地 clone，SKILL.md v3.7.1，208 KB / 4141 行）
- 关联：修正 ADR-0002（选 AKShare）与 ADR-0003 §9.1（零成本路径）

## 一、它是什么

一个 Claude Code skill：**单文件 SKILL.md，内嵌全部可运行 Python**，
11 层 · 47 端点 · 15 个数据源 · 零鉴权。作者自己的定位是**纯数据层**——
没有编排、没有 agent、没有契约、没有报告生成。

质量很高，而且是**实测导向**的：每个端点都带踩坑注释和实测日期，
有一手封禁案例、有阈值表、有备用源速查。这不是拼凑的文档。

## 二、决定

> **不替换机制，只吸收数据层的知识与实现。**

理由不是"我们的更好"，而是**两者根本不在同一层**：

| | a-stock-data | 本项目 |
|---|---|---|
| 解决的问题 | 怎么把数据取回来 | 怎么让一群 agent 可靠地产出一份可审计的复盘 |
| 产物 | DataFrame / dict | `report.json` + 九章报告 + 行为自检 |
| 失败时 | 抛异常 / 返回空 | `blocked` 产物 + 顶部声明 + 可追溯 provenance |
| 形态 | 一个 208 KB 的 markdown | 7 agent / 9 skill / 7 schema / 状态机 / 186 个测试 |

"把全套机制换成它"实际是删掉后一列，换来一份取数说明书。

四条具体的不能换：

1. **它没有 blocked 语义。** 我们"绝不编造"是靠契约兜住的——缺数据会产出一个
   可审计的产物，而不是一个异常。这条是整个系统的底线，不能换成"代码抛错"。
2. **内嵌 markdown 的代码没法测试。** 我们那 186 个测试守的是规则：
   盘中不入库、降级源不入库、单笔风险 0.5%、每个持仓恰好一个动作、403 不重试。
   搬过去全部消失。
3. **教学目标相反。** 这个项目要讲清楚"组件如何咬合"，
   而单文件恰好把咬合关系全藏起来了。
4. **208 KB ≈ 6–7 万 token。** 加载一次就超过我们一整轮复盘的输入量。
   刚做完预算和仓库来省请求，不该在上下文上反向浪费。

## 三、要吸收的（按价值排序）

### 3.1 已落地：东财限流加严到 1.0 秒

它整理的社区实测阈值（2026-05）：**>5 次/秒 · 单 IP 并发 ≥10 · 1 分钟 ≥200 次**
触发风控。它的限流器默认间隔就是 1.0 秒。

我们原来是全局 0.4 秒，对东财偏松 → 已改成分域名：
`EM_MIN_INTERVAL=1.0`（东财）/ `MIN_INTERVAL=0.4`（其余）。

更有说服力的是它记录的一手封禁案例（2026-06-30）：
10 线程并发、完全不限流、1 小时 45000+ 请求 →
**push2 全系列 IP 级封禁持续 20 小时以上**。
和我们 8-31 那次是同一种事故，只是量级更大。

### 3.2 已落地：403 不重试、不降级

它明确写：**403 不重试（东财风控信号，重试无益反而加重）**。

我们原来把 403 和断连一样对待，会重试 3 次、还会走"绕代理 / 换 IPv4"两条降级——
而换出口试探正是风控最讨厌的行为。已改：403 直接抛错并说明"重试无用"，
降级阶梯对 403 返回空。对照测试保证断连仍然重试。

### 3.3 已落地：确认「按域名熔断」是对的

它的一手案例里有一条关键观察：
**`datacenter-web.eastmoney.com` 不受影响——东财不同子域走不同 WAF，
`push2` 被封不代表整个东财都不能用。**

我们的熔断器本来就是 per-host 的，这条从外部证实了那个设计是对的：
如果按"eastmoney.com"整体熔断，会在还有一半接口可用时自己把自己关掉。

### 3.4 待落地：涨停池的独立备胎（修正 ADR-0003 §9.1）

ADR-0003 §9.1 写过「涨停池免费只有东财网页接口」。**这个判断需要修正。**

它的 §8.2 用的是同花顺 `data.10jqka.com.cn/dataapi/limit_up/limit_up_pool`，
**独立域名、独立风控面、零鉴权**，返回：涨停原因题材、封板成功率、
板型（换手板/一字板/T字板）、炸板次数、几天几板、首次涨停时间。

能覆盖：涨停家数、连板梯队、题材归因（比东财还多）。
**不能覆盖**：炸板池与跌停池——所以「炸板率」的分子仍然只有东财有
（它自己的备用源速查表也承认「打板层暂无独立备胎」）。

修正后的说法：**涨停梯队有免费独立备胎，炸板率没有。**

### 3.5 待落地：mootdx / 腾讯作为行情主源

它的优先级原则和我们 ADR-0003 §四的结论是同一条，只是它已经实现了：

> 能用通达信(TCP)/腾讯(HTTP，实测不封)，就别用东财；
> 东财只用于它独有、别处拿不到的数据。

对我们意味着：指数日线、个股行情、实时价这些**根本不该走东财**。
东财只留给涨停池、板块资金流、龙虎榜这几样独家数据——
请求量因此还能再降一截，而且降的正好是高风险的那部分。

### 3.6 待落地：备用源速查表 → `config/datasources.yaml`

它那张十类数据 × 独立备胎的表，正好是我们 ADR-0003 §四那张表缺的实现细节。
直接作为 `datasources.yaml` 的填充材料。

## 四、要重新考虑的一件事：还要不要 akshare

它 V3.0 移除了 akshare，理由是：

> akshare 本质是对东财/同花顺/新浪公开 API 的封装，中间层增加了故障点
> （版本兼容 bug、pandas 3.0 ArrowInvalid 等）。直连底层 HTTP，零中间依赖。

**这条对我们成立。** 回看 `memory/knowledge/akshare-gotchas.md`，
我们踩的坑里有相当一部分不是数据源的问题，是 akshare 这一层的问题：

- 1077 个 `requests.get` 不带 timeout → 无限挂起（我们打了猴子补丁）
- `index_zh_a_hist` 取 K 线前先请求 `80.push2` 拉对照表 → 一个纯粹多余的故障点
  （我们打了第二个猴子补丁）
- 字段偶尔变更

我们现在是**给一个中间层打补丁**，而直连只需要几十行。

但**不在这次改**。理由：直连要重写全部 fetch 模块，风险集中；
而且 akshare 的价值（一个函数名对应一类数据、学生查得到文档）对教学是真实的。
路径应该是：先按 §3.5 把 provider 层建起来，
新 provider 直连、旧 akshare 保留为其中一个 provider，逐块迁移、逐块对账。

## 五、明确不取

- **单文件内嵌代码的形态**——与可测试性和教学目标都冲突
- **iwencai 语义搜索**——需要 API Key，破坏"零门槛"
- **ETF 期权层 / 舆情互动层 / 宏观层**——九章复盘用不到，不引入
- **它的估值公式与调研流程**——那是它的分析逻辑，我们的分析逻辑在 `agents/` 和
  `skills/` 里，由用户自己填 `TODO(strategy)`，不该被外部项目的框架替掉

## 六、许可

它是 Apache-2.0（仓库里有 LICENSE）。抄实现要保留出处：
迁移过来的 provider 文件头部注明「实现参考 a-stock-data v3.7.1 §x.y」。

## 七、§3.5 落地记录（2026-09-01）

### 做了什么

建了 `scripts/providers/`：**做什么**（要一份持仓快照）和**谁来做**（腾讯批量 /
东财逐个 / 仓库读回）拆开，优先级写在 `config/datasources.yaml` 里而不是代码里。
8-31 被封那天我们没有任何一个开关能说"这块数据改走别处"，这一层就是补那个开关。

### 最大的一处改动：持仓快照

改造前 `fetch_holdings_quotes` 是**每只持仓一个东财请求**。
10 只持仓 = 每天 10 个东财请求，而这正是防封铁律点名的头号成因：

> 批量场景 AI 跑循环逐个拉，是被封的头号元凶

改造后拆成两半：

| | 之前 | 之后 |
|---|---|---|
| 当日快照 | 东财 × N | **腾讯 × 1**（一个请求拿全部持仓，不封 IP） |
| 90 日历史 | 东财 × N | 本地仓库；只有缺的交易日才联网 |

稳态下持仓这块的东财请求数从 N **降到 0**。

### 个股不能像指数那样存

指数日线永远不变，个股的**前复权历史会被除权改写**——而且不会报错，
只是安静地和现在的口径对不上。

处理：`_qfq_drift()` 拿新取到的重叠日期和仓库里的比一比，
对不上就把这只票的存量整个作废重取。比"永不复用"省，比"无脑复用"对。
数据集名带口径（`stock_daily_qfq`），不同复权方式永不混存。

### 指数日线暂时没动

腾讯 `fqkline` 能拿 OHLC，但**它的成交额字段我在这台机器上没法联网核对**
（cloud 容器和本机 VM 都到不了 gtimg）。而按位置解析的接口字段错一位，
"成交额"可能读成"换手率基点"，差三个数量级——那会让章节①的两市成交额整个失真。

所以指数日线保持东财主源。要推进这一步，先在你自己机器上跑：

```bash
python tools/verify_provider.py            # 同一天同一只票，两个源逐字段对账
```

对不上就别设主源。**宁可多发几个请求，也不要在报告里放一个错的数。**

### 顺带处理的两个"静默拿错数据"

都是照抄 a-stock-data 的处理，因为它们比报错危险：

1. **000001 是歧义码**——`sh000001` 是上证指数，`sz000001` 是平安银行。
   只看首位会路由到深市拿回平安银行的报价，不报任何错。用沪市指数白名单挡住。
2. **僵尸报价**——停牌股/废码照样返回 200 + 一份定格在最后交易日的报价。
   判据：成交额 0 且现价==昨收 → 标 `is_stale`，绝不当成当日真实成交。

- 去 akshare 化（§四，要等 provider 层稳定后逐块迁移）
