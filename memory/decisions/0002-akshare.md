# ADR-0002：选 AKShare 作为唯一数据源

- 日期：2026-08-28
- 状态：**部分被取代**（见 ADR-0003 数据源分层；AKShare 由「唯一数据源」降级为「L3 补缺源」）
- 取代：`0002-akshare-for-ohlcv.md`（该版只覆盖 OHLCV，在系统改为「每日九章复盘」后范围已不够，本文件扩展为全量数据源决策）

## 背景

需要：四大指数行情与分时、涨停/炸板/跌停池、板块行情与资金流、个股行情、新闻与公告。
候选：AKShare、Tushare Pro、BaoStock、自建爬虫。

## 决定

**全部数据走 AKShare。**

## 理由

1. **零门槛** —— 免费、不需要 token、不需要积分。这对教学项目是决定性的：
   学生 `pip install` 完就能跑，不用先去注册账号攒积分。
2. **覆盖最全** —— 涨停池、炸板池、连板数、板块资金流这些**短线复盘必需**的数据，
   Tushare 要高积分，BaoStock 根本没有。
3. **一个源，口径统一** —— 混用多个源最大的成本不是代码，是口径对不齐。

## 已知代价（写代码时已处理，见 memory/knowledge/akshare-gotchas.md）

- 背后是第三方网页接口，**会限流、会抽风** → `scripts/ak_client.py` 做了重试与本地缓存
- 接口字段偶尔变更 → 取数层按列名取值而非按位置，变更时报错而不是静默错位
- 分时数据只保留最近几天 → 历史回测拿不到日内四段
- 炸板/跌停池只有最近 30 个交易日

## 何时该重新考虑

- 需要做**多年历史回测**时（AKShare 的分时与涨停池窗口太短）
- 需要**盘中实时**（秒级）数据时
- 出现持续性限流导致每日复盘跑不完时

到那时的路径是"AKShare 为主 + 某个付费源补历史"，而不是整体替换——
因为涨停池这类数据仍然只有 AKShare 免费提供。
